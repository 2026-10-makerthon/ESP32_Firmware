사용자 요청으로 DM161을 DC ERM으로 가정한 초기 출력 프로파일을 추가했다. 기존 배선의 DRV 전원3.3V는 유지한다. TI SLOS854D 식6으로 OD_CLAMP=138(0x8A),명목 평균 출력2.97942V를 계산했고 기동 boost를 끈다. 자동 보정과 ROM 효과는 사용하지 않는다. 기존5ms 패턴을 signed RTP0..127로 출력한다. 모터의 전압 표기3/3.7V와80mA는 제공 정보로 보존하며, 정격 범위나 기동 피크를 새로 확정하지 않았다.

`-RealMicrophone -PhysicalHaptic` 빌드는 `hardware/profiles/xiao-dm161-3v-prototype.json`을 선택하여 실제 출력을 활성화한다. `SH_HW_OUTPUT_ENABLED=1`, `SH_HW_PROTOTYPE=1`, `SH_HW_VERIFIED=0`으로 구분한다. BLE UUID·패킷·opcode는 유지하며 로컬 초기 출력 허용 상태에서만 미검증 출력 명령을 수락한다. Capabilities bit0과 GET_STATE HARDWARE_VERIFIED는0이다. 기존 미확정 기본 프로파일의 일반 빌드는 출력을 계속 거절한다.

전체 PC·네이티브 회귀 테스트는 **93 passed**다. 실제3V 프로파일로 생성한 헤더와 실제DRV C 코드를 가짜I2C에 연결하여 레지스터 순서·강도·정지·오류 latch를 실행했다. C/Python 초기 출력 허용·검증 bit 유지·heartbeat 만료도 비교했다. 실제 보드 플래시,전기 출력·전류,모터 기동·촉각,무선·휴대폰 연동은 아직 시험하지 않았다.

## 2026-10-30 XIAO 배선 적용

모터 추가 식별: 사용자가 **DM161, 80mA, 3V와3.7V 모두 표기됨**으로 알려주었다. 프로파일에 두 전압을 남기고 정격전압은 미확정으로 되돌렸다. 초기 출력 설계 목표3.0V를 별도로 기록했으며 실제 적용/측정된 제한값은 아니다.80mA는 기동/구속 피크인지 확인되지 않아 `peak_current_ma`에 넣지 않았다. 현 배선의 드라이버 전원3.3V는 유지한다. 모터 종류·피크전류·구동 보정은 미확정이다. 출력은 계속 비활성화되어 있으며 기존 펌웨어 바이너리의 동작은 바뀌지 않았다.

사용자 표의 INMP441 WS1/BCLK2/SD4, DRV2605L SDA5/SCL6, 버튼 GPIO7에 맞췄다. OFF에서3~6초 누른 뒤 놓으면 일반 부팅,6초 유지하면 페어링 부팅,ON에서3초 유지하면 출력·BLE 종료 후 버튼 해제를 기다려 RTC EXT0 딥슬립에 들어간다. OFF는 배터리 차단이 아니다.

NVS에 한 기기의 Secure Connections Just Works 키를 보존하고 일반 부팅은 저장 기기만 허용한다.6초 부팅은 이전 키를 지우고120초 등록을 허용한다. 암호화/본딩/16byte 키 확인 전 앱 데이터 접근을 차단한다. 기존 v1 UUID·opcode·ADPCM·명령·패턴은 유지한다. 클라이언트에 `hil --pair`를 추가했다. 상세 절차는 [XIAO 사용법](XIAO_OPERATION.ko.md)을 따른다.

DRV2605L I2C signed RTP 어댑터를 추가했다. 기존5ms 논리 패턴을 실행하고, 오류에서 RTP0/standby를 시도하며 재개를 막는다. 현재 프로파일의 모터 종류·정격·피크전류·보정값은 미확정이므로 실제 출력은 비활성화되어 있다. EN을 GPIO로 제어하지 않는 배선에서는 I2C 단선/MCU 정지 시 하드웨어 출력 차단을 보장할 수 없다.
